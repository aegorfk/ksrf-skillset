# Среда для документов

Контейнер запускает существующий локальный цикл КС РФ: регистрацию материалов,
извлечение текста, OCR и экспорт рабочего DOCX/PDF с превью. Он нужен, когда на
компьютере нет подходящего Python, LibreOffice или средств распознавания.
Обычный запуск плагина и исследование переданных текстов контейнера не требуют.

Образ содержит Python 3.13.15, LibreOffice Writer, Poppler, Tesseract с русским и
английским языками, свободные шрифты и точные Python-зависимости из
`skills/ksrf-complaint-cycle/configs/plugin-requirements.txt`. Он запускается под
пользователем `10001:10001`. Код установлен в `/opt/ksrf`; досье хранятся отдельно
в `/cases` либо в выбранной внешней папке.
Небольшой адаптер `soffice.py` создаёт для каждой конвертации отдельный временный
профиль LibreOffice и cache/config в `/tmp`; домашний каталог пользователя не
меняется. Поэтому конвертация работает и с `--read-only`, и с UID владельца
подключённой папки. Временный профиль удаляется при завершении команды.

## Сборка

Docker должен быть установлен и запущен. Распакуйте собранный плагин и откройте
терминал в его корне: рядом находятся `skills/`, `environment/` и `LICENSE`.
Не используйте папку с личными делами как контекст сборки.

```sh
docker build -f environment/Dockerfile -t ksrf-applicant:local .
docker run --rm --network none ksrf-applicant:local --help
```

Сборка скачивает публичный базовый образ, системные пакеты и Python-библиотеки.
Её последний шаг выполняет полный синтетический smoke под обычным пользователем;
ошибка чтения, OCR или экспорта останавливает сборку. Материалы проверки создаются
во временной папке и удаляются после неё. Частные документы и ключи для сборки не
нужны. `Dockerfile.dockerignore` ограничивает контекст исходниками плагина.

Базовый официальный образ зафиксирован digest, а Debian-пакеты берутся из
подписанного снимка `20260901T000000Z`. Проверка срока снимка отключена потому,
что используется архив; проверка подписи пакетов остаётся включённой. Это
воспроизводимый набор исходных зависимостей, без обещания одинаковых байтов
конечного образа на разных архитектурах. Для обновлений безопасности нужно
обновить digest, дату снимка и Python-pins, затем повторить smoke. Установленные
версии записаны в `/opt/ksrf/python-packages.txt` и `system-packages.txt`.

## Проверка с сохранением результата

Следующий запуск создаёт только синтетическое дело. Пример для macOS/Linux
использует UID/GID текущего пользователя, чтобы файлы в подключённой папке
принадлежали ему. UID не должен быть нулевым. В Docker Desktop для Windows
можно использовать пользователя образа по умолчанию; права подключённой папки
проверяются отдельно.

```sh
mkdir -p smoke-output
docker run --rm --network none --read-only \
  --user "$(id -u):$(id -g)" \
  --tmpfs /tmp:rw,nosuid,nodev,size=512m \
  --mount "type=bind,src=$PWD/smoke-output,dst=/cases" \
  --entrypoint python ksrf-applicant:local \
  /opt/ksrf/environment/smoke.py \
  --workspace /cases/check-1 --expect-unprivileged
```

Папка `check-1` должна быть новой. Результат включает исходный учебный DOCX,
журнал регистрации, рабочие DOCX/PDF, изображения страниц, список пробелов и
`smoke-report.json`. Проверяются хеши, сохранность пометки рабочего проекта,
повторное чтение PDF и реальное распознавание изображения. Отдельно проверяется,
что строгий выпуск остаётся заблокирован, а `human_review=pending`,
`filing_authority=false` и `release_eligible=false` сохраняются. Это проверка
программы, а не юридической эффективности или вероятности принятия жалобы.

Для временной проверки без сохраняемой папки:

```sh
docker run --rm --network none --read-only \
  --tmpfs /tmp:rw,nosuid,nodev,size=512m \
  --entrypoint python ksrf-applicant:local \
  /opt/ksrf/environment/smoke.py --expect-unprivileged
```

## Работа с досье

Подключайте только папку выбранного дела. При повторных запусках сохраняйте её
по тому же пути внутри контейнера: журнал содержит абсолютные пути к файлам.
Агент выполняет штатные команды `start`, `intake`, `writing` и `render draft` и
готовит входные JSON сам. Редактировать JSON заявителю не требуется.
Обновление образа не должно заменять папку дела.

Пример создания нового дела в папке `cases`:

```sh
mkdir -p cases
docker run --rm --network none \
  --user "$(id -u):$(id -g)" \
  --mount "type=bind,src=$PWD/cases,dst=/cases" \
  ksrf-applicant:local start --profile basic \
  --matter-id applicant-review --workspace /cases/applicant-review --json
```

`--network none` подходит для работы с уже переданными файлами. Официальные сайты
проверяются доступным браузером пользователя/хоста: браузер не входит в этот
образ. Подключения CasusLegal, HUDOC, Firecrawl, корпуса, доверенные одобрения и
учётные записи также не переносятся автоматически.

## Известные пределы

- Старый `.doc` штатный сборщик читает через macOS `textutil`, а при его отсутствии
  использует ограниченный `strings`. В этом Linux-образе нельзя считать такой
  результат полноценным чтением. Сначала сохраните копию в DOCX через LibreOffice,
  сохранив оригинал, затем повторите инвентаризацию и проверку текста.
- Для PDF резервный OCR штатно ограничен первыми восемью страницами. Агент должен
  явно задать необходимое `--ocr-pages` и сверить число страниц; короткий прогон
  не означает полного чтения длинного скана. Отдельные картинки обрабатываются
  целиком, но качество распознавания всё равно проверяется по изображению.
- Свободные шрифты могут менять переносы относительно установленного Microsoft
  Word. Просмотр всех страниц PDF остаётся отдельным шагом.
- Контейнер не запускает HTTP-сервер, не открывает порт и не выполняет публичное
  развёртывание. Его сборка не подключает инструменты к ChatGPT в браузере.
  Выполнение команд в ChatGPT зависит от возможностей конкретного хоста;
  установленные skills и доступный внешний runtime — разные состояния.
- Подпись, платёж, подача и юридическое одобрение не выполняются smoke или образом.

Рецепт следует официальным рекомендациям Docker по
[фиксации образа и контексту сборки](https://docs.docker.com/build/building/best-practices/)
и [инструкциям Dockerfile](https://docs.docker.com/reference/dockerfile/).
Профиль конвертера задаётся штатным
[параметром LibreOffice UserInstallation](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html).
