# Verification record

## Scope

The release adds constitutional-comparative-research to the explicit package allowlist and connects it to argument-patterns, practice-authority-builder and rights-argument-builder. The primary applied outcome is a better-founded Russian constitutional problem and argument. Standalone comparison remains supported.

Eight method cards from five constitutional courts were selected for varied reasoning operations. Ten published anchors match the retained canonical text and their quote hashes; all six distinct retained original files match their SHA-256. A second reviewer read the source context and checked the method descriptions. Five official pages could be reopened; three live opens failed and were supported by retained official originals. Current applicability and subsequent case law are not exhaustively verified. Raw documents and extended research notes remain outside this repository.

## Behaviour observed

A separate executor read the skill and relevant references without reading evals or their expectations, and answered three synthetic requests:

1. Compared two foreign adequacy tests without inventing a Russian dispute or an automatic CPI obligation.
2. Converted a nominal pay-growth argument into a conditional Russian question about the function of payments; preserved missing domestic law, application, ordinary-remedy and admissibility issues.
3. Attributed an inflation claim to the applicant and did not turn the court's refusal to decide the general question into either acceptance or rejection of that claim.

A separate source-bound diagnostic read three KSRF and two VSRF acts about wages. It distinguished a possible normative defect from an ordinary failure to investigate the payment mechanism, retained adverse authority and rejected an automatic foreign-to-Russian CPI entitlement. The two VSRF texts are third-party reproductions and were not independently checked against official PDFs. This diagnostic used no new applicant's case file.

These are development observations, not an independent legal-outcome holdout, an ablation comparison or evidence of better filing success. The eleven committed synthetic scenarios and ten trigger examples are reproducible evaluation inputs; merely validating their JSON does not execute them.

## Technical evidence

The candidate extractor was exercised on the actual foreign library and with targeted tests for exact offsets, restarts, changed source attribution, rejected-record continuation, alias protection and read-only source access. Its output remains discovery-only and distinguishes versions from unique passage candidates. It never asserts a court speaker, adopted holding or verified Russian support.

Release checks include strict source validation of all sixteen packages, offline self-containment, a separate-directory installation, runtime validation, the complete root test suite and skill-local test suites run in separate processes. The repository contains multiple test directories named tests, including a package with __init__.py; collecting all of them in one pytest process causes namespace collisions in the current environment. Root tests are run with their own explicit tests namespace, and skill suites are run separately. No failing test is excluded by that separation.

Publication uses one scoped atomic commit from the verified live main base, followed by a live remote SHA comparison and global installation from the clean published checkout. The post-commit live verification and installed-runtime reports are recorded by the publication tools outside the repository; this source record does not claim those future checks have already passed.
