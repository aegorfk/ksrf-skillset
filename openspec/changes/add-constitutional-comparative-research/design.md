# Design

1. Основной режим в KSRF-контексте — поиск российской нормативной проблемы и поддержка аргументации жалобы с помощью иностранных приёмов. Самостоятельное сравнение сохраняется для прямого запроса без российского применения. Проверка российского права, применения и компетенции обязательна для российского вывода; иностранный суд не становится обязательным источником РФ.
2. Единица анализа — конкретная цепочка мотивировки с установленным автором и функцией. Большинство, особое мнение, сторона, редакционный тезис и сообщение о деле разделяются до синтеза.
3. Сравнение хранит norm/subject/interference/test/evidence/reasoning/result/remedy/time; разные результаты объясняются через существенные различия. Отбор по одному удачному исходу и частота цитат не обосновывают конвергенцию.
4. Проверенные методические карточки дают триггер, операцию, необходимые посылки, контрпример и переносимый исследовательский вопрос. Карточки происходят из конкретных актов и не утверждают актуальность всего направления практики.
5. Машинное извлечение использует явные многоязычные маркеры, сохраняет точные offsets и hashes; результат остаётся `discovery_only`, роль не угадывается. Локальный review читает полный текст/контекст до интеграции в навыки.
6. Извлекатель поддерживает JSONL и явно заданную foreign-library SQLite, открываемую read-only короткими запросами. Он не открывает живую HUDOC SQLite. Отдельная очередь/состояние возобновления находятся вне исходного корпуса; изменение текста или версии извлекателя повторно ставит документ на разбор.
7. Публикация: 16 пакетов в контракте, manifest, структурные/поведенческие проверки, clean-room install, независимая проверка, один scoped commit в canonical main и проверка remote SHA перед глобальной установкой. Изменения существующего runtime предварительно сверяются с опубликованным base.
