# Design

The evidence model remains unchanged: its section codes, sentence IDs, evidence links and approvals are internal data. A deterministic presentation layer groups court-facing sections into the macrostructure. The working exporter no longer mutates sentence text to add review labels, and never adds a draft notice. Only explicitly separated `review_notes` are exported to the companion report. The required `adverse_material` section remains substantive content in section II, without a workflow heading; its text must never be silently discarded. A writer moves actual service notes to `review_notes` explicitly, preserving the source and reason in the report. Unknown additional substantive sections are retained in the reasoning section rather than discarded.

The visible document begins with the right-side address/applicant block and the existing two-line title. Formal norm and admissibility particulars form unnumbered introductory prose. The numbered sections are facts (including judicial stages), the applicant's constitutional reasoning, and the request; enclosures and signature follow. The legal IRAC progression guides paragraph content, not Latin administrative headings. The renderer does not invent a representative or infer one from another proceeding.

The renderer highlights explicit placeholder spans in yellow without altering their text. A missing section in a provisional draft receives an explicit placeholder; review-only missing sections remain in the report. Documentary source text, paragraph order within each component, adverse findings, unknown support states and IDs remain available in the source record. Dates and signatures are supplied explicitly; missing date/signature fields are highlighted in the provisional export.

A separate Markdown report stores readiness flags, missing data, review findings and review-only content. The provisional manifest retains false filing/approval/release authority and adds explicit `filing_ready=false`. Hash checking covers the companion report as well as document files. Strict release remains blocked by unresolved placeholders and evidence gates. The renderer changes presentation only; it does not rewrite uncertain claims into certain ones or sanitize a caller's legal assertions silently.

A bounded marker guard blocks known service phrases in court-facing sections and preserves the full mixed sentence in the separate report. It is not a general semantic classifier; editorial review remains mandatory. Strict render and package routes also produce a hash-bound Markdown report. Existing release packages remain compatible without the new optional report kind; new packages include it and verify it like other declared artifacts.

Public tests use synthetic input only. Verify document XML (title, macro-headings, placeholder highlighting, absence of generated notices/review IDs), preservation of adverse facts and evidence states, companion content, false authority, hash freshness and existing release regressions. Perform a synthetic DOCX/PDF visual check when local document tools are available. Publish one scoped commit only after manifest/privacy/skill/runtime/OpenSpec checks, verify live main SHA, recheck the saved global baseline, then install the published version.
