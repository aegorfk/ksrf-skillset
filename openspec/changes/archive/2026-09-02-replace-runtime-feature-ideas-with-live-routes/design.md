## Context

The three `complaint-patterns.md` files are installed and linked from core case-triage, facts/demands, and rights-argument skills. Their methodology is useful, but their final roadmap blocks describe absent product components as if the user can call them. The installed judicial-meaning acquisition guide has the inverse drift: it still calls an already shipped and executable `PracticeAnalysisGate` a future contract. A source-only automation backlog already exists outside the installed payload, so runtime copies should contain current executable routes rather than future-product names.

## Goals / Non-Goals

**Goals:**

- replace every installed future-feature block with a route that resolves inside the runtime payload;
- reduce the audited payload-only scan for `Идеи функциональности` and `будущий контракт автоматизации` from four matches to zero;
- preserve the underlying user goals without claiming automation;
- keep official-source, exact-locator, adverse, transfer, coverage, and human-choice boundaries explicit;
- preserve every other paragraph of the three references byte-for-byte;
- make the three owning backlinks describe operational checks rather than ideas or optional examples;
- verify source and clean-room routes, forbidden roadmap wording, and exact reviewed digests.

**Non-Goals:**

- implement an indexer, clusterer, recommender, selector, tracker, database, service, or connector;
- merge or delete the three reference files in this change;
- choose a principal argument or remedy for the user;
- infer preservation from memory instead of an exact lower-court document and locator;
- turn SКO commentary or any index into an official KSRF authority;
- rewrite historical archived OpenSpec records or the source-only automation backlog.

## Decisions

1. **Rewrite the blocks in place.** Stable file paths and all surrounding legal methodology remain intact.
2. **Use five common live routes.** Each file points to shipped guidance for similar-position research, practice mapping, remedy options, argument portfolio, and preservation review. The rights guide may add the shipped SКO methodology route because its existing block uniquely names that source family. The common block also names the real candidate keys emitted by `ksrf_autocollect.py` and links to their authoritative runtime boundary table.
3. **Use real Markdown links.** Every local route must resolve to a regular file in the canonical runtime payload and in a clean-room installation.
4. **Make outputs and gates explicit.** Position search returns candidate `ResearchFinding` records; practice review produces a bounded table/ledger; remedy work produces primary and narrower options; portfolio work exposes alternatives; preservation requires document, date, stage, exact locator, and the norm/constitutional proposition preserved.
5. **Do not simulate absent products.** Remove the headings and exact product labels `Индексатор`, `Builder`, `Конструктор`, `Рекомендатель`, `Selector`, and `Трекер`, plus automatic clustering/selection/persistence implications.
6. **Update backlinks.** The three owning skills describe the file as executable checks and routes, not as ideas or optional drafting examples.
7. **Preserve outside-block bytes.** A regression projects each file around the replaced block and compares it with the frozen base, preventing unrelated methodology drift.
8. **Correct the live practice-analysis description.** Replace only the stale future-contract sentence in `judicial-meaning-evidence-acquisition.md`; the new sentence points to the shipped `practice-analysis-integration.md` route and reiterates that the reference alone neither runs collection nor proves practice or filing authority.

## Risks / Trade-offs

- **A useful goal is mistaken for removed functionality** → retain every goal as a named route with output and stop condition.
- **Links exist in source but not after install** → resolve every local link against both the source payload and a clean-room copy.
- **Manual route sounds automated** → forbid product-role names and require human choice for remedy and portfolio decisions.
- **Practice mapping overclaims coverage** → require a bounded population/query frame, exact legal meaning, inclusion/exclusion, adverse material, and coverage limits.
- **Preservation becomes a checkbox** → require an exact lower-court document and locator; missing proof remains a gap.

## Migration Plan

1. Freeze the three targets, backlinks, runtime membership, roadmap tokens, and baseline digests.
2. Add RED tests for forbidden claims, preserved outside-block content, real routes, clean-room installation, outputs, and human gates.
3. Rewrite the three blocks and backlinks, correct the stale `PracticeAnalysisGate` sentence, and update public documentation.
4. Pin final digests, regenerate the manifest from live `main`, and run focused/full/source/runtime/OpenSpec verification plus independent reviews.
5. Publish one atomic merge, verify live SHA, install globally, archive this change, regenerate the manifest from the merge SHA, and publish the evidence commit.

Rollback is the exact prior `main` commit; no data or schema migration is involved.
