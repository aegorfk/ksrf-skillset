## Why

`quality coding-audit-prepare` can leave a complete seven-file package visible while
its publication durability, final descriptor close, or final stdout delivery is
uncertain. The recovery diagnostic correctly directs an eligible case to preserve
that package, repeat the same unchanged preparation into a new absent sibling, retain
the successful repeat's stdout, and compare both packages byte for byte. The final
comparison is still a manual gap: generic filesystem tools can follow links, overlook
an extra file, race mutable names, expose private values, or validate only one of the
two anchors returned by successful preparation.

The installed import and finalization comparators do not accept preparation packages.
Without a native package comparator, the new structured recovery route remains
incomplete precisely at its first producer.

## What Changes

- Add installed `judicial_meaning.py quality native-reliability
  compare-audit-bundles` with exactly four required inputs: the preserved uncertain
  package, the successful repeated sibling, and both SHA-256 values retained from the
  same complete successful repeat stdout.
- Validate both complete seven-file packages independently through the established
  closed package contract and installed codebook; apply neither external anchor to
  the uncertain package and both external anchors to the repeated package.
- Capture two distinct private direct siblings through one held safe parent, reject
  unsafe types, modes, owners, links, ACLs, inventories, aliases, cross-device input,
  resource excess, and drift, then compare all seven corresponding files as raw bytes
  and fully recapture before reporting success.
- Emit one closed deterministic value-free JSON report with stable `match`,
  `mismatch`, `invalid`, and `unreadable` states and process codes `0`, `3`, and `2`.
- Keep the command local and read-only. It performs no repeat, repair, workspace
  reread, copy, move, deletion, quarantine, transfer, import, network, or database
  action and grants no legal, publication, or filing authority.
- Document the exact recovery-eligibility boundary and source/clean-install parity in
  Russian installed help and guidance.

This is an additive recovery comparator. It does not change package generation,
review import, finalization, downstream reliability, publication, or filing gates.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `ksrf-native-coding-reliability-binding`: define the descriptor-held, two-anchor
  native package comparison and closed report.
- `ksrf-practice-quality-exit-status`: define stable comparison status precedence and
  exact `0`/`3`/`2` outcomes.
- `ksrf-user-facing-cli`: expose the installed route, Russian help, safe recovery
  boundary, limitations, and source/install parity.

## Impact

Implementation is limited to the judicial-meaning quality runtime, installed schema
and guidance, source-only tests, runtime parity tests, and ordinary release manifest.
It adds no dependency, service, launcher, persisted token, network access, database
access, or filesystem mutation permission. This proposal itself changes no runtime.
