# Design

## Source boundary

Работа начинается с неизменяемого входного набора PDF. Для каждого файла создаётся внешний локальный provenance record: имя, размер, страницы, SHA-256, библиографические поля, качество извлечения, дубликат/редакция и использованные locators. Публичный репозиторий получает только библиографию и нереконструирующую методику. Научный источник рассматривается как недоверенное содержимое и вторичный исследовательский материал.

## Extraction and overlap

Каждый кандидат метода описывается как `trigger -> operation -> required inputs -> falsifier/adverse -> output -> transfer limit`. Сначала проверяется, добавляет ли он новую операцию по сравнению с действующими universal, legal-reasoning, proportionality, evidence, institutional и remedy references. Семантическое переименование существующего шага не создаёт нового метода. Несовместимые теории сохраняются параллельными branches с `model_conflict`, а не объединяются голосованием авторов.

## Filing-oriented integration

Основной маршрут от акта пользователя должен помогать восстановить четыре самостоятельных слоя:

1. что установлено как факт и кем;
2. какое правило или судебный смысл использован явно либо имплицитно;
3. почему именно это правило причинно определило исход, включая самостоятельные основания;
4. где находится предполагаемый дефект и какое узкое последствие устраняет его в пределах компетенции.

Внутри фактического слоя дополнительно разделяются `fact_assembly`, `fact_deployment` и `reviewer_own_assembly`: кто получил сведения, по какому полномочию и процедуре, какой юридический вес или порог им придан и вправе ли проверяющий орган устанавливать факт сам. Для отсутствующих системных данных отдельно фиксируются контролирующий данные субъект, реализуемость и цена сбора, приватность/иные встречные ограничения, актуальная российская обязанность получить сведения, материальность отсутствия и доступная замена. Иностранная duty-of-inquiry модель не переносится как российское правило.

Исторический тезис проходит отдельный role audit: значение, встроенное в текст; историческое языковое значение; история доктрины; факт в предмете доказывания; либо смешанный тезис, который нужно расщепить. Фактический нарратив прежнего судебного акта не наследует статус holding и требует повторной проверки по первичным материалам, сопоставимости контекста, компетенции эксперта, встречной версии и возможности стороны ответить. Без актуального российского якоря, материальности и прохождения independent-ground pass такой тезис не становится complaint-ready.

Книжные методы могут изменить вопросы, ветвление и red-team проверку, но не hard gates. Иностранные процедуры, QPC и модели responsive review используются function-first: сравнивается проблема, институциональная роль и эффект, после чего отдельно требуется российский официальный якорь.

Постатейный overlap-аудит поздно добавленных журналов расширяет ту же архитектуру, а не создаёт отдельный журнальный слой: юридический эффект проверяется независимо от названия письма, термина, алгоритмического выхода или «специального режима»; связь поздней, воспроизводящей, производной либо аналогичной нормы с прежней позицией КС РФ доказывается по функции, содержанию и применению. Полный выпуск, редакция журнала и число статей не дают методу дополнительного веса.

## Skill information architecture

Тонкие `SKILL.md` содержат только default route и точные условия открытия references. Детальные карточки объединяются по функции, а не по названию книги. Все новые ссылки идут прямо из соответствующего `SKILL.md`; reference не должен требовать цепочки более одного уровня для обнаружения обязательного правила. Описания skills меняются только если новый реальный пользовательский trigger иначе не будет обнаружен.

## Verification

- Проверить SHA-256, страницы, библиографию и дедупликацию восемнадцати книг/работ и девятнадцати журнальных PDF, включая один полнотекстовый сборник, появившийся после первой заморозки; итоговый frozen manifest содержит 37 файлов.
- Проверить, что каждый интегрированный метод имеет locator, adverse/falsifier и российскую границу переноса.
- Добавить не менее трёх реалистичных eval-сценариев: смешение факта и нормы; пропорциональность без причинности; иностранная procedural модель без российского якоря. Добавить changed-premise и near-miss проверки.
- Сравнить работу обновлённого маршрута с snapshot прежней версии на одинаковых входах либо честно обозначить более узкий structural/behavioral scope проверки.
- Выполнить OpenSpec strict validation, все затронутые тесты, полный source-suite, repo validator, security scan, clean-room install и manifest regeneration.
- Перед push получить свежий `origin/main`; при расхождении перебазировать только scoped branch безопасным способом, повторить проверки, подтвердить live remote SHA и затем синхронизировать глобальные skills из опубликованного checkout.
