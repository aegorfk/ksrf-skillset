# Проверяемый цикл написания и редактирования жалобы

## Why
Методология уже требует точного конституционного вопроса, оснований доводов и сильных возражений. Рабочий экспорт создаёт документы, но не сохраняет связанный редакторский цикл «концепция → абзацы → замечания → предложенная редакция → повторная проверка». Пользователь согласовал первую очередь: пункты 1, 2, 3 и 5.

## What Changes
- Добавить локальный маршрут writing: plan, compose, review, revise, status.
- Сохранять краткую концепцию и выбор ведущей формулировки, карту оснований каждого аргумента, точные фрагменты источников, возражения и показываемые изменения.
- Связывать замечание с конкретной версией абзаца; изменение абзаца возвращает замечание на повторную проверку.
- Создавать отдельный render-payload.json для действующего render draft без изменения исходника и без переноса юридических approvals.
- Разрешить автоматическое предложение редакции при сохранении исходника, объяснения правок и человеческого принятия.

## Impact
Глобальные ksrf-complaint-cycle, ksrf-complaint-qa, ksrf-argument-patterns; CLI, документация, синтетические тесты и source-only проверочный сценарий. Без нового внешнего сервиса, LLM-вызовов, правовой классификации допустимости или изменения строгого release. Пункты 4, 6 и независимый юридический эксперимент 7 не объявляются выполненными.
