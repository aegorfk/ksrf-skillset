## Why

Обычная установка успешно завершается, но перед понятным сообщением показывает
служебную англоязычную строку publication guard с идентификатором репозитория и
четырьмя внутренними хеш-полями. Для
пользователя это визуальный шум, тогда как тот же прямой CLI нужен сопровождающим
для доказуемой публикации.

## What Changes

- Обычный `./install.sh` после успешной проверки публикации скрывает служебный
  stdout вложенного publication guard и показывает только краткий русский
  результат установки и безопасную команду настройки окружения.
- Ошибка publication guard по-прежнему останавливает установку до записи,
  сохраняет ненулевой код и не допускает сообщения об успехе или `export`.
- Прямой `tools/verify_publication_state.py`, его JSON и подробный maintainer-вывод
  остаются без изменений.
- README объясняет пользовательский результат и отдельный maintainer-маршрут.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `ksrf-skillset-install-transaction`: уточнить публичный вывод успешной обычной
  установки и разделить его с подробной проверкой публикации для сопровождающих.
- `ksrf-skillset-install-status`: сохранить совместимость режимов проверки,
  уточнив узкое изменение только успешного stdout обычной установки.

## Impact

Затрагиваются `install.sh`, регрессионные shell-тесты, README и соответствующий
OpenSpec-контракт. Состав runtime-навыков, транзакционная логика, сетевой guard,
его прямой CLI и коды выхода не меняются.
