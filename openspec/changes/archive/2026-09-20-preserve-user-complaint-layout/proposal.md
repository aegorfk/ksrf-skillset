## Why

A user's latest edited DOCX can contain deliberate paragraph boundaries, deleted requests and case-specific citation choices. Rebuilding from an older Markdown or template can silently undo those choices. The reusable format also needs an explicit request marker and a stable single-row date/signature arrangement.

## What Changes

- Make the latest user-designated DOCX the editorial baseline and preserve its paragraph divisions, selected requests and deletions within the authorized scope.
- Define a separate bold centered request marker, retaining the user's capitalization, and a date-left/signature-right row made with fixed tab stops or a borderless table.
- Reconcile cited case records, the annex list and actual files; repair list gaps only within the user's authorized numbering correction.
- Respect case-specific source restrictions without turning them into universal bans or suppressing internal source and adverse review.
- Clarify that alternative remedies are research options, not a required number of requests in every complaint.

## Capabilities

### Modified Capabilities
- `ksrf-complaint-presentation`: preserve the current user revision and its source/remedy scope.
- `ksrf-document-formatting`: specify request/signature layout and authorized package reconciliation.

## Impact

Methodology and documentation only. No new renderer, automatic DOCX merge, legal rule, runtime feature or filing permission. Private source documents and case facts are excluded from publication.
