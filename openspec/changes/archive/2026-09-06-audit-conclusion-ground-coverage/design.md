## Context

The published baseline is f149f401f104b4be213fe82f3c1e5b3c867b9683. A read-only code audit confirms that missing edges yield no propagated question, and that an impact path does not enumerate an unaffected second ground. Both are intentional runtime boundaries, not newly discovered defects.

Existing methods already cover evidence provenance, cross-instance causation and remedy design. The missing integration is a repeatable review of the drafter's own conclusions and their surviving support. A private original complaint/replies set is being re-read for role, scope and conditional-reasoning counterexamples; it is retrospective, not a held-out quality trial.

## Goals / Non-Goals

Goals: operationalize backward review; distinguish joint support, alternative sufficient chains, conditional argument and mere rebuttal; preserve uncertainty and demand scope. Make the result readable and attach it to existing versioned review artifacts where useful.

Non-goals: semantic dependency extraction, AND/OR theorem proving, new packet fields, automatic objection closure, a new admissibility rule, a source publication, or a measured claim of improved legal quality.

## Decisions

1. Use one focused QA reference, linked from compose and premise-change instructions. Do not lengthen every entrypoint with the full method.
2. Audit exact conclusions and each distinct requested result, including procedural requests when present; record reviewed and pending scope, not a completeness score.
3. Identify the target, the actor asserting each proposition, support and inference separately. Start from the actual record, never from the desired outcome to invented premises.
4. Use a counterfactual editorial operation: temporarily withhold the changed premise, without declaring its negation true or deleting source text. Reconstruct a supported chain at the same scope and identify shared hidden prerequisites.
5. A conditional fallback requires an explicit condition and a supported consequence; rejecting an opponent's reason does not establish the applicant's claim. Independent grounds for a court's outcome and grounds supporting the applicant's argument are distinct objects.
6. Reuse writing review/revise fields and the full current draft; the impact report supplies triggers, not all remaining grounds. No extra JSON contract is claimed.

## Risks / Trade-offs

- Too much bookkeeping: apply to material conclusions and requested results, reuse existing cards, avoid an all-sentence Cartesian graph.
- False certainty: source review and two technical probes demonstrate a limitation and a plausible method, not independent legal improvement. Human review and existing legal gates remain.
- False rejection: an unknown premise blocks only its dependent assertion or release stage, not independent research or a labelled draft.
- Privacy: originals, excerpts and private paths stay outside Git; public change contains only non-reconstructive method.
