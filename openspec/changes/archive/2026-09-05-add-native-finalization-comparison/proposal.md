## Why

Native coding finalization already tells a user to repeat unchanged inputs into a
new absent sibling and byte-compare the two four-file directories after an eligible
durability, finalization, or confirmation uncertainty. That comparison is still a
manual prose step. Generic filesystem tools can follow links, omit an unexpected
entry, race mutable names, reveal private paths or digests, or turn equality into a
broader authority claim. The installed reliability doctor cannot fill the gap: it
reads only two individual files and does not enforce the private sibling-directory
contract or compare all four outputs.

## What Changes

- Add the installed nested command `judicial_meaning.py quality native-reliability
  compare-finalizations` with exactly three required inputs: the uncertain
  finalization directory, the newly repeated sibling, and the finalization receipt
  SHA-256 retained separately from the repeat's complete successful stdout.
- Capture two distinct direct siblings through one held safe parent; require the
  exact four-file private finalization inventory, bounded no-follow reads, stable
  identities, single-link files, Darwin ACL absence, and a complete final recapture.
- Revalidate each receipt's closed contract, strict canonical receipt-file bytes and
  unsigned-object self-digest; all three receipt-to-other-file byte digests; the
  uncertain directory's internal reliability relation; and the repeated directory's
  externally anchored native relation before reporting exact four-file byte equality.
- Emit one closed, deterministic, value-free JSON report with stable `match`,
  `mismatch`, `invalid`, and `unreadable` states and process codes `0`, `3`, and `2`.
- Keep the command local and read-only. It performs no repeat, repair, copy, move,
  deletion, quarantine, import, attachment, promotion, network, or database action.
- Make the route, exact options, eligibility boundary, negative authority scope, and
  source/clean-install parity discoverable in Russian help and installed guidance.

This is an additive diagnostic/recovery comparison. It does not change the native
finalization artifacts, the existing doctor, or any downstream claim-use gate.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `ksrf-native-coding-reliability-binding`: define the exact externally anchored,
  descriptor-held four-file comparison and its closed value-free report.
- `ksrf-practice-quality-exit-status`: define comparison state precedence and exact
  `0`/`3`/`2` process outcomes without changing existing commands.
- `ksrf-user-facing-cli`: expose the installed nested route, Russian help, eligible
  recovery boundary, limitations, and source/install parity.

## Impact

A later implementation is limited to the existing judicial-meaning quality library,
CLI parser, installed practice-quality schema and guidance, focused tests, runtime
parity checks, and the ordinary release manifest refresh. It adds no dependency,
launcher, service, persisted recovery token, filesystem mutation permission, network
access, or database access. Runtime, skills, schemas, tests, and manifests are not
changed by this proposal-only change.
