## Context

Full acts are reachable through the official portal even when a general search index does not expose them or one HTTP client's certificate store fails. A decision file may be attached under the later date of preparation of reasons. The official case number can be padded or retain a previous-year number, and a higher-court copy can contain a conflicting UID year.

## Goals / Non-Goals

Goals: reach full available acts autonomously, preserve a reproducible path and byte provenance, distinguish transport failure from publication status, and make the route discoverable from a single supplied PDF.

Non-goals: new network client or automatic collector, CAPTCHA solving, disabling TLS checks, determining legal admissibility, publishing private evidence or modifying court records.

## Decisions

1. Expand entrypoint triggers; keep the detailed Moscow procedure in one linked reference.
2. Prefer independent queries using observed fields instead of combining every constraint; retain raw identifiers and record verified aliases.
3. Once one card is verified, follow its related-instance and inventory links; do not keep searching alternative queries except when resolving ambiguity or explicitly testing retrieval.
4. Retrieve actual DOC/RTF/PDF/HTML bytes, validate content and extract complete text; a card or a 200 protection page cannot close a full-act slot.
5. Try an available independent client or browser after a client-specific error. Check routing before changing VPN; no TLS bypass or automatic configuration change.
6. Keep local receipts and historical links as discovery aids. Revalidate them and retain new evidence so later reviews do not regress to an empty index search.
7. Add synthetic scenarios to the existing runtime reference contract. Structural checks and live route checks are reported separately; neither establishes legal readiness or universal retrieval reliability. Existing scenarios that permit a question receive explicit prior-search conditions.
8. Increment the source plugin manifest to 1.0.2. After canonical publication, build with the clean-release guard, publish the generated companion marketplace and checked archives, then refresh the registered marketplace and reinstall with the supported CLI. Verify the installed source SHA and changed file hashes; current-task reload is not assumed.

## Risks / Trade-offs

Portals change and transient 503 responses occur. Document observed form fields and navigate current UI when they change. Padded/substring search can match a different procedural list; require court, parties, dates and related numbers. Year variants of UID require source evidence, never blind mutation. Multiple byte-identical official copies share any textual errors and do not independently resolve them.

## Validation

Check all runtime changes against fresh canonical source; run strict skill validation, offline self-containment and relevant existing source tests. Review synthetic hard negatives. Verify a complete route from official search to card and full bytes for both instances and record transport/content/identity/dates/hashes privately. Use clean-room install and release checks before one atomic publication.
