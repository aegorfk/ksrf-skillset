# Design

Keep one canonical source in ksrf-skillset. Generated marketplace/ZIP packages
remain distribution outputs. Use one original text SVG asset for both logo and
composer icon so the public-source boundary does not admit arbitrary binary case
material. Brand asset inclusion is an exact allowlist; validate SVG geometry and
exclude scripting/external resources before packaging.

Directory checks cover the documented skills-only package path: length-limited
listing fields, bundled square icons, preserved 16-skill closure and deterministic
integrity manifests. The existing runtime tests and Docker evidence are reused
only when the runtime/environment input hashes are unchanged.

Reviewer fixtures are synthetic text, with expected behavior and actual execution
evidence recorded separately. No real applicant record is included. Five positive
and three negative examples support reproducible review without claiming model
quality validation.

The public manifest keeps the existing repository author attribution. Verified
publisher identity belongs to the portal; normalization must use the actual
selected identity, not a fabricated name. Country availability and policy
attestations are not invented in offline artifacts.

Portal creation, upload scan, submission, approval and public publication are
distinct states. A blocked identity check does not prevent completing independent
package work, but prevents claiming a created/submitted draft.
