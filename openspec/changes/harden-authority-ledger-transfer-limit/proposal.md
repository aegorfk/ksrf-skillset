# Fail-closed проверка `transfer.limit` в authority ledger

## Зачем

Валидатор реестра авторитетов сначала фиксирует ошибку типа поля `transfer.limit`, но
при `drafting_ready=true` затем повторно вызывает `.strip()` на исходном значении.
Массив, объект или число поэтому превращают обычную ошибку входа в необработанный
`AttributeError` с traceback. Это нарушает границу безопасной CLI-валидации и может
скрыть остальные диагностические сообщения.

## Что меняется

- использовать результат типовой проверки `transfer.limit` перед проверкой его
  непустоты;
- сохранять существующий код выхода `1` и формат `ERROR:` для структурно неверного
  реестра;
- добавить офлайн-регрессию для контейнеров и числовых значений, а также проверку
  валидной строковой ветки;
- уточнить контракт authority ledger и связать изменение с OpenSpec.

## Рамки

Входит в объём: одно поле `authorities[].transfer.limit` в standalone validator,
тесты и контрактный текст.

Не входит: полный JSON Schema, семантика переносимости авторитетов, сетевые запросы,
изменение статусов или публикация skillset/глобальная установка.

## Capabilities

### Modified Capabilities

- `ksrf-practice-authority-builder`: типовая ошибка в `transfer.limit` должна быть
  контролируемой и не должна вызывать traceback.

## Acceptance

- Значения `[]`, `{}`, `null`, `false`, `1` и `1.5` дают код `1`, содержат
  `ERROR: ...transfer.limit: expected string` и не содержат `Traceback`.
- Строковое значение продолжает проходить ту же ветку без traceback; другие
  инварианты реестра не меняются.
