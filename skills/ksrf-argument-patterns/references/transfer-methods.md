## Как работать без ответа будущего суда

Сначала выпиши из доступного акта: применённую норму и редакцию, приписанный
ей смысл, факт, который суд счёл решающим, самостоятельные основания отказа
и реально оставшийся способ защиты. Отдельно подпиши: довод стороны,
суждение суда, цитируемая практика, собственная гипотеза. Слова «суд указал»
в пересказе жалобы ещё не доказывают авторство тезиса.

Далее найди возможный механизм, а не готовый результат. Используй карточку
только если её trigger совпал с материалами. Докажи необходимые условия;
проверь каждое опровергающее условие и сильнейшее возражение. Unknown сохраняй
как неизвестность, а не отрицание. Если ни одна карточка не подходит,
сформулируй новую гипотезу из нормативного механизма.

Новая формулировка связывает **норму в конкретном смысле → типовую ситуацию →
механизм вреда → конституционный критерий → узкую проверку/коррекцию**.
Конституционный критерий и полномочие на коррекцию требуют самостоятельных
первичных опор. Вопрос из карточки — шаблон исследования, не готовый вывод КС.

## Что меняют эти карточки

| Приём | Что проверять вместо поверхностного совпадения |
|---|---|
| Связанные сделки | Кто реально организует выбор, какие договоры связаны и где возникает разрыв защиты |
| Сравнимые группы | Цель гарантии и статус на юридически значимую дату, а не биографическое сходство |
| Факт и документ | Доказательственная или правообразующая функция формы; равноценность альтернативы |
| Полномочие и ресурсы | Обычные собственные расходы или бремя, причинённое другим публичным уровнем |
| Непоглощение гарантий | Разные функции гарантий либо двойное возмещение той же потери |
| Последствия нового правила | Сумма, число актов, статус, исполнение и пересмотр как разные вопросы |
| Выгода от нарушения | Не улучшает ли положение должника неисполнение дополнительной обязанности |
| Ошибка и добросовестность | Кто ошибся, какова ошибка и что именно сделал получатель |
| Перезапуск срока | Появилось ли существенное новое знание, а не только новый документ |
| Эффект процедуры | Сохраняется ли защитный смысл отбора после последующего усмотрения |
| Асимметрия информации | Поведение обеих сторон и опровержимость, а не автоматическая ответственность |
| Окончательность | Тождество сторон, требования и обстоятельств, а не сходство правовых тем |

Примеры границ: формальная аффилированность не делает всех участников
солидарными должниками; другой документ не заменяет правосоздающую форму;
новые существенные сведения могут оправдать новый срок; выигранный конкурс
не тождествен бессрочному назначению; отсутствие исполнения не доказывает
вину контролирующего лица; ошибка органа не исключает доказанный обман
получателя. Эти возражения способны изменить результат, а не добавляются
только для полноты изложения.

## Проверяемая карточка конкретного дела

Сохраняй `issue_frame`, `lower_court_meaning`, `premises`, `mechanism`,
`constitutional_anchor`, `counterargument`, `transfer_limit`, `remedy_boundary`,
`evidence_windows` и `unknowns`. Не объединяй самостоятельные основания
отказа: устранение одного из них может не менять результат.

В ретроспективном разборе отдельно записывай `observed_before_target` и
`learned_from_target`. Второе — материал обучения/критика оценщика, никогда
не слепой вход. Даже очевидная после чтения КС формула не является доказанным
прогнозом по нижестоящему акту. Отсутствие слов «Конституция» и «соразмерность»
не исключает структурного довода: спор о доказательстве, сроке, составе
выплат или доступе к процедуре может содержать его посылки.

## Необязательная техническая проверка

`python3 scripts/check_transfer.py INPUT.json` запускается из каталога этого
скилла и работает без сети и исходного корпуса. Все conditions перечислены
в JSON соответствующего метода. Пример одного условия:

```json
{
  "value": true,
  "evidence": [{
    "source_sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
    "locator": "синтетический акт, абзац 4",
    "source_role": "lower_court_reasoning",
    "source_checked": true
  }]
}
```

Верхний объект содержит `method_id`, `mode: "prospective"`, `as_of` в формате
YYYY-MM-DD и `conditions` со всеми необходимыми и опровергающими условиями.
Синтетический hash выше не использовать для реальных доказательств. Значение
false тоже требует проверенного окна; пропущенное условие и null дают Unknown.

Выходы: `candidate` — технически заполненный кандидат, `needs_evidence` —
нехватка доказательств, `not_applicable` — необходимая посылка опровергнута,
`blocked` — есть опровергающее обстоятельство или нарушен контракт.
Код выхода 0 только для candidate, 2 для остальных. Проверяются структура
якоря и логика условий, **не истинность доказательства и не качество жалобы**.

## Временная граница релиза

Методическая реконструкция датирована 2026-09-05, получена из evaluator-only
материала; агентский разбор не является юридическим одобрением человеком.
Карточки автономны, но автономность не означает историческую чистоту.
Весь этот релиз запрещён в историческом EVAL независимо от удаления имён,
номеров постановлений и цитат. Релиз нельзя датировать датой старого акта.

Для будущих независимых тестов заранее зафиксируй snapshot скилла, базовую
модель и доступные источники; группируй связанные дела до разделения выборок.
Исследователь, уже читавший target, не является слепым predictor для того же
дела. Справочный индекс с target и производными остаётся у оценщика;
фильтр по дате на таком индексе сам по себе не легализует исторический EVAL.
