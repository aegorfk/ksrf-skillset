# Понятный вход для заявителя

Этот справочник задаёт вход в существующий полный цикл. Он не меняет юридические критерии, полномочия человека или интерфейсы специализированных навыков. Пользователь может не знать терминов и впервые обращаться в суд.

## Начни с того, что уже есть

Подходят обычный рассказ, номер или УИД дела, ссылка на судебную карточку, отдельный файл, несортированная папка, проект жалобы, письмо Секретариата или акт КС РФ. Не делай УИД обязательным. Не проси заново прислать уже доступный материал.

Если содержательных материалов нет, предложи начать без длинной анкеты:

> Помогу разобрать документы, понять возможный путь и подготовить проект обращения. Начать можно с описания ситуации, номера дела или любых документов. Сначала покажу, что удалось установить, чего не хватает и какой следующий шаг имеет смысл.

Если материал передан, сразу разбирай его и дай первый полезный результат: краткую карточку ситуации, опись, замечания к проекту либо объяснение полученного документа. Не выдавай человеку технический план вместо выполнения работы.

По документам самостоятельно установи участников, предмет спора, судебные стадии, даты, нормы-кандидаты и непосредственное последствие. Сохрани неизвестное и противоречия. При наличии нескольких дел разделяй их по содержанию актов, не только именам файлов. Сканы требуют проверки извлечённого текста по изображениям; сомнительная дата не становится установленной после OCR.

Доступные официальные материалы ищи самостоятельно. Номер дела может быть неоднозначным: установи суд, год и принадлежность по имеющимся данным; уточни только неразрешимое различие. CAPTCHA, отказ доступа или отсутствие опубликованного полного текста остаются конкретным пробелом поиска.

## Среда и первый запуск

Сначала выясни, какие инструменты действительно доступны в текущей сессии: чтение вложений, браузер, выполнение Python, запись файлов, конвертация DOCX/PDF, OCR и постоянное хранилище. Наличие файла скрипта не доказывает возможность его выполнить. Установка плагина не переносит историю автора, его учётные записи, корпуса, данные дел или одобрения.

Назови доступные профили коротко:

- **Базовый** — разбор документов, официальные источники, исследование и рабочий проект. Рекомендуемый начальный режим, если пользователь не выбрал другой.
- **Расширенное исследование** — дополнительные источники и поисковые инструменты при собственном доступе пользователя.
- **Экспертная проверка** — отдельный контур проверок и подтверждений; его работоспособность надо установить, а юридическое решение принимает человек.

Сохрани точный результат диагностики, но объясняй пользователю последствия для его задачи: «Текст PDF прочитан; на двух страницах нужны изображения», «DOCX можно создать; преобразование в PDF здесь недоступно». Не заставляй выбирать профиль до первого анализа. Отсутствие дополнительного сервиса не останавливает независимые действия базового маршрута.

При локальном исполнении переносимый адаптер находится в `scripts/plugin_runtime.py` относительно корня этого навыка. Агент сам вызывает `doctor`, при поручении подготовить среду — `setup --documents`, существующий цикл через `run -- <аргументы ksrf.py>`, сбор файлов через `collect -- <аргументы ksrf_autocollect.py>`. Он сам подготавливает входы и читает отчёты. Это дополнительный способ запуска; прямые существующие CLI сохраняются. Установка зависимостей нужна только в среде, где она разрешена и соответствует поручению пользователя; не проси повторное разрешение на уже порученную подготовку среды. Системные компоненты и внешние сервисы не считаются установленными по одному успешному Python setup.

Если исполнения нет, используй доступные инструменты чата, веди явную опись и создавай только те артефакты, которые реально поддерживаются. Дай текстовый проект и список пробелов, если невозможно получить DOCX/PDF. Не сообщай о запуске doctor, сохранённом локальном деле, проверенных хешах, OCR или визуальном просмотре, которых не было.

Локальные дела и состояние среды храни вне каталога установленного навыка. Документ, загруженный в ChatGPT, уже передан сервису ChatGPT; не называй такую обработку локальной. Для дополнительной передачи частного документа в подключаемый сервис примени существующий privacy gate с конкретными данными и адресатом. Не останавливай из-за этого работу с уже доступными материалами.

## Порядок работы по ситуации

**Первое дело:** cycle → triage + exhaustion → исследование вариантов → выбор человеком → facts-demands + rights-argument-builder → независимая QA → формальная проверка. Каталог исследовательских навыков подключай по реальной задаче. Все 16 навыков доступны; не запускать все подряд ради отметки о покрытии.

**Дело ещё рассматривается:** проверь процессуальную стадию, затем возможность маршрута court-request-motion. Ходатайство стороны, запрос суда и индивидуальная жалоба различаются; не обещай, что один документ заменяет другой.

**Готовый проект:** сохрани оригинал, сверь материалы, привяжи замечания к конкретным абзацам, подготовь отдельную редакцию в пределах поручения и проверь её заново. Не заставляй повторять полный старт, если состояние дела уже доступно. Существенные новые материалы возвращают зависимые выводы на проверку.

**Неполное дело, но просят написать:** сохрани рабочую концепцию и ясно обозначенный проект с пробелами. Отсутствие подтверждения блокирует зависимый вывод и строгий выпуск, а не все исследования и черновую работу. Не заполняй неизвестное догадкой.

**Письмо Секретариата:** установи вид документа по тексту. Для каждого указанного недостатка покажи требуемое исправление, относящийся к нему документ и проверенный источник срока. Письмо Секретариата, судебный отказ и итоговый акт имеют разные роли; не выводи последствия из слова «отказ» в рассказе пользователя.

**После акта КС РФ:** сначала decision-execution по полному акту. Регистрация обращения, изучение, принятие к рассмотрению, итоговый акт и восстановление права — отдельные события. Не обещай автоматического пересмотра по чужому делу.

**Самостоятельное исследование нормы или зарубежных подходов:** используй соответствующий исследовательский маршрут без выдуманного личного дела. Его результат не получает статус допустимой жалобы. Ограничения доверенной проверки внутри конкретных научных или эмпирических маршрутов сохраняются.

## Объясняй результат и следующий шаг

Начни с ответа на запрос. Когда это помогает делу, покажи пять коротких частей: что установлено; что не подтверждено; возможные варианты; подготовленные файлы; следующий шаг. Пустые части не нужны. Существенный факт и юридический тезис должны вести к источнику и точному месту, а подробный технический журнал остаётся отдельным артефактом.

Различай три вопроса: **что умеет среда**, **какие материалы доступны**, **что подтверждено по делу**. Успешная установка или экспорт не закрывает юридические пробелы.

| Внутренний результат или условие | Понятное объяснение |
|---|---|
| Доступен анализ, но не хватает существенного акта | «Можно продолжить исследование. Для вывода о … нужен полный акт …» |
| `FIX_FIRST` | «Сначала нужно устранить конкретный пробел: …» |
| `COURT_REQUEST_ROUTE` | «Проверим возможность ходатайства перед судом, который рассматривает дело» |
| `NO_GO_KSRF` | «По проверенным обстоятельствам этот путь не подходит, потому что …»; покажи основание и доступные независимые действия |
| `ABSTAIN_PENDING_RECORD` | «Пока нельзя сделать вывод по …: не получен …» |
| `GO_TO_KSRF` | «Есть основания продолжить подготовку и передать позицию на юридическую проверку»; это рекомендация, не одобрение |
| `working_draft_created` | «Создан рабочий проект. Вот что ещё требует проверки» |
| `ready_for_expert_review` | «Материалы подготовлены для юридической проверки» |
| `ready_for_human_signing_filing` | «Проверен конкретный комплект перед действиями человека»; покажи версию, незавершённые человеческие действия и границы выполненной проверки |

Не показывай процент успеха, вероятность принятия или общий зелёный статус на основании количества актов, хешей и тестов. Не называй проект готовым к подаче при существенных неизвестных. Без действительного доверенного подтверждения соответствующие переходы остаются недоступны; имя проверяющего, самозаявленный JSON и обычное сообщение в чате не создают техническое удостоверение.

Задавай узкий вопрос только о недоступном факте, документе или выборе между уже объяснёнными вариантами. Не требуй от заявителя заранее выбрать статью Конституции, доказать применение нормы, заполнить JSON или выполнить CLI. Первое использование юридического термина сопровождай коротким объяснением. Уважай собственное описание человека, одновременно отделяя его утверждение от содержания документов и вывода суда.

Подписание, платёж, направление документов и юридическое одобрение выполняются человеком. Не останавливай разрешённую подготовку из-за этих будущих действий: сначала подготовь конкретный проверяемый результат и объясни оставшийся человеческий шаг.
