Используй этот справочник, когда дефект затрагивает одновременно положение заявителя и воспроизводящий его нормативный механизм. Сравнительные remedial models дают варианты и вопросы QA, но не расширяют компетенцию КС РФ.

## Жёсткий competence gate

Перед включением любого элемента в вопрос, просительную часть или план исполнения одновременно установи:

1. `official_russian_authority` — российский нормативный якорь;
2. `competent_actor` — орган, который вправе создать требуемый эффект;
3. `applicant_status` — статус заявителя и применимый маршрут;
4. `permitted_effect` — точный допустимый юридический результат;
5. `execution_mechanism` — как результат перейдёт в дело и практику;
6. актуальный смысл мотивировочной и резолютивной частей акта КС РФ, если он уже вынесен.

Если хотя бы одного элемента нет, вариант остаётся `comparative_only`, research/QA lead или предложением законодателю.

## 1. Две независимые дорожки

Заполни обе колонки. Пустую дорожку сопровождай проверяемой причиной, а не предположением, что другая автоматически её заменяет.

| Поле | Индивидуальный контур | Системный контур |
| --- | --- | --- |
| Устраняемый вред | | |
| Практический результат | | |
| Российский нормативный якорь | | |
| Компетентный адресат | | |
| Процессуальный канал | | |
| Временной горизонт | | |
| Временная защита | | |
| Доказательство исполнения | | |
| Риск неисполнения или побочного эффекта | | |
| Причина исключения контура | | |

QA:

- индивидуальный результат не должен оставлять воспроизводящий механизм без анализа;
- системный результат не должен оставлять заявителя без допустимого практического маршрута;
- системность не означает автоматически более сильную или подходящую защиту;
- remedy должен зеркалить только доказанные элементы нормы, применения, вреда и компетенции.

## 2. Single-track red team

Для индивидуального варианта проверь:

- остановит ли он повторение дефекта;
- не создаёт ли привилегию или `queue-jumping` без нормативного основания;
- не перекладывает ли системные издержки на лиц, не участвовавших в деле;
- не становится ли узкая временная мера скрытым общим регулированием.

Для системного варианта проверь:

- получает ли заявитель своевременный практический результат;
- не продолжается ли необратимый вред до реформы;
- учтены ли интересы затронутой группы, а не только институциональное удобство;
- способен ли названный адресат исполнить результат;
- не просит ли проект постоянного надзора, которого российское право не предусматривает.

## 3. Матрица выбора варианта

Сравни каждый допустимый вариант:

| Поле | Вопрос |
| --- | --- |
| `remedial_goal` | Какой точный дефект и вред устраняются |
| `evidence_of_effect` | Чем подтверждён ожидаемый эффект |
| `fit` | Связан ли вариант с дефектом причинно |
| `less_restrictive_option` | Есть ли столь же действенный, но менее вредный вариант |
| `applicant_effect` | Что и когда получает заявитель |
| `third_party_effect` | Кто ещё выигрывает или несёт издержки |
| `system_effect` | Прекращает ли вариант воспроизводящий механизм |
| `authority_and_route` | Есть ли компетенция и downstream-процесс |
| `failure_mode` | Что произойдёт при бездействии или частичном исполнении |

Самое мягкое средство не предпочтительно, если оно оставляет дефект. Самое сильное не предпочтительно, если выходит за компетенцию или создаёт несоразмерный побочный эффект.

## 4. Пакет риска необратимого вреда

Для временной или немедленной защиты зафиксируй:

- конкретный вред, вероятность и временную близость;
- связь вреда с назначением защищаемого права;
- почему позднее восстановление или компенсация недостаточны;
- силу основного правового довода;
- минимально достаточный объём защиты;
- права третьих лиц и публичный интерес;
- возможность пересмотра меры при новых фактах;
- российское процессуальное основание.

Не презюмируй необратимость из одного названия права.

## 5. Время и принудительность

Не своди remedy к одной шкале `сильное/слабое`. Отдельно зафиксируй:

- время: `immediate` или `delayed`;
- эффект: `declaratory`, `interpretive`, `coercive` либо иной предусмотренный российским правом;
- адресата;
- событие запуска;
- срок;
- состояние заявителя до запуска;
- способ проверки результата.

Категории `monopoly power`, `blind spot`, `inertia` и модели responsive remedy Dixon/Yap можно использовать только как сравнительные гипотезы о рисках. Они не являются российской квалификацией.

## 6. Отложенный или диалоговый вариант

Диагностическая карточка содержит:

| Элемент | Что установить |
| --- | --- |
| Нормативный результат | Какой минимум должен быть достигнут |
| Свобода выбора средств | Что адресат вправе выбрать сам |
| Дорожная карта | Последовательность допустимых действий |
| Срок | Источник, длительность и начало течения |
| Временная защита | Что происходит с заявителем и риском вреда |
| Участие | Кто представляет затронутых лиц и на каком основании |
| Отчёт/индикатор | Как доказать не формальный процесс, а результат |
| Контроль | Кто вправе проверять исполнение |
| Fallback | Заранее известный законный результат бездействия |
| Trigger | Проверяемое событие, запускающее fallback |
| Эскалация | Существующий российский маршрут при провале |

Не создавай `penalty default`, структурный интердикт, консультации или постоянный надзор из одной сравнительной модели. Без прямого российского основания эти элементы остаются вопросами к законодателю и QA исполнения.

- `RemedyComparisonMatrix`;

- список `comparative_only` элементов и способ их российской проверки.
