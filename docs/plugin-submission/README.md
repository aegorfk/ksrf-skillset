# Подача ksrf-applicant в общий каталог

GitHub-дистрибуция и локальная установка доступны отдельно от публикации в
универсальном каталоге OpenAI. Подготовленная версия 1.0.1 сохраняет все
16 навыков и исполняемый код версии 1.0.0. Выпуск включает обновления
методических инструкций из b6bad1e, оформление карточки, документацию
и проверки сборки. Итоговый состав runtime проверяется заново.

Идентификатор verified identity, публичное имя издателя и география не
выдумываются при сборке. `aegorfk` в пакете обозначает автора репозитория и
само по себе не подтверждает личность в OpenAI Platform. Если портал предлагает
нормализацию имени по выбранной проверенной личности, проверить соответствие
перед загрузкой/отправкой и сохранить фактическую версию полученного draft.

## Пройти подачу

1. В [OpenAI Platform](https://platform.openai.com/plugins) выбрать нужную
   организацию и **Create plugin → Skills only**.
2. Если портал требует проверенную личность до создания draft, издатель
   завершает **Individual** или **Business verification** в настройках своей
   организации. Это отдельный шаг; установка плагина не выполняет его.
3. Загрузить проверенный `ksrf-applicant-web-1.0.1.zip` из
   [выпуска 1.0.1](https://github.com/aegorfk/ksrf-applicant-plugin/releases/tag/v1.0.1).
   Сверить SHA-256 с `SHA256SUMS`. Не создавать MCP-сервис для этого skills-only
   пакета: он не содержит MCP-конфигурацию.
4. Проверить считанные навыки, краткое название, описание, оба значка, выбранную
   verified identity и доступные поля формы. Внести prompts и reviewer cases,
   когда соответствующие поля доступны.
5. Выбрать только подтверждённые издателем страны доступности. Русский язык и
   предмет российского права не означают доступность OpenAI в любой стране.
6. Дождаться scan results, исправить конкретные ошибки. Заявления о соблюдении правил
   и юридически значимые подтверждения принимать только по точному тексту и проверенным обстоятельствам.
7. После **Submit for Review** сохранить идентификатор заявки, время, package
   hash и показанный статус. После одобрения выполнить отдельный **Publish** и
   проверить появление карточки в общем каталоге.

Общая инструкция предлагает 5+3 теста и публичные URLs всем издателям.
Более конкретный справочник ошибок помечает ряд этих требований как remote-MCP
only и делает website/support/privacy/terms optional для skills-only ZIP.
Решающими для фактической обязательности остаются выбранный тип заявки и поля
портала; подготовленные дополнительные материалы не означают наличие MCP.

## Проверки и фиксация статуса

Проверка сборки охватывает длины listing-полей, безопасный квадратный SVG,
полный состав навыков и целостность дистрибуции. Upload scan и решение OpenAI
этим не заменяются. Положительный smoke подтверждает программный путь, а не
юридическую правильность ответа модели по делу.

Хранить внешнюю квитанцию отдельно от исходников: `source_commit`,
`distribution_commit`, `package_sha256`, состояние verified identity без её
частных документов, `draft_created`, `upload_scan`, `submitted_for_review`,
`approved`, `published` и публичный URL карточки, если он реально получен.
Не записывать в публичные файлы сведения KYC, номера документов, cookies,
учётные данные или материалы пользователей.

Источники требований, проверенные 2026-09-12:
[Submit plugins](https://developers.openai.com/plugins/deploy/submission),
[Submission errors](https://developers.openai.com/plugins/deploy/submission-errors),
[Use plugins](https://learn.chatgpt.com/docs/plugins).
