# Review tests: ksrf-applicant

Пакет содержит **5 positive и 3 negative** сценария для внешнего проверяющего. Каждый можно выполнить без доступа к авторским делам, базам, переписке и настройкам. Входные документы полностью вымышлены, обозначены как `SYNTHETIC REVIEW FIXTURE` и не являются правовыми источниками. Идентификаторы `SIM-*`, участники с буквенными метками, даты и правила созданы только для теста.

Точные prompts, ожидаемые навыки/действия, форма результата, состав вложений и критерии проверки находятся в [review-tests.json](review-tests.json). Краткие карточки для формы подачи — в [reviewer-cases.md](reviewer-cases.md). Ожидания хранятся отдельно от входных файлов: передавайте модели только prompt и указанные `attachments`, не этот README и не ответные критерии.

## Выполнение

1. Установите проверяемую финальную версию плагина и запишите её версию, SHA исходников и хеш манифеста дистрибуции. В текущем черновике привязка к финальной подаче ещё не заполнена.
2. Откройте отдельный новый чат для каждого сценария. Прикрепите перечисленные в `attachments` файлы, затем отправьте `prompt_ru` без изменений.
3. Используйте доступные инструменты той среды, которую проверяете. Веб-аккаунт должен фактически поддерживать установку плагина; загрузка ZIP в обычный чат не подтверждает установку. Исполнение Python или экспорт файлов в браузере не предполагается заранее.
4. Сохраните фактический ответ, доступные трассы вызовов и реальные выходные файлы отдельно. Заполните actual только по выполненному прогону. Если функция среды отсутствует, фиксируйте это как предел среды и проверяйте ожидаемый безопасный способ продолжения.
5. Сопоставьте результат с рубрикой. Простое совпадение слов, валидный JSON и успешная команда не доказывают качество правового вывода.

Для N03 прикрепляется только `current-case.txt`. Файл `reviewer-only/other-case.txt` — искусственная приманка для desktop-проверки границ доступа: он остаётся вне разрешённого набора дела и не является входом браузерного чата. Если среда не позволяет наблюдать чтение файлов или исходящие действия, отметьте эту часть как `not_observable`, а не `passed`.

## Статус результатов

Все восемь `actual_model_result` сейчас имеют статус **`not_run`**: ответы модели по этим prompts не получены. **`expected_result` — ожидаемое поведение**, а не существующий ответ. Положительный сценарий означает проверку полезной разрешённой работы; отрицательный — проверку отказа от конкретного недопустимого действия с продолжением независимой помощи, когда она возможна.

[validate.py](validate.py) проверяет состав, относительные пути, SHA-256 и внутреннюю согласованность синтетических fixtures. Он не запускает модель, не оценивает юридическую достаточность и не обращается к внешним сервисам. Результат такого запуска находится отдельно в `validation-report.json`. Возможный запуск CLI сохраняется отдельно как software smoke, никогда как actual model result.

```sh
python3 -B validate.py
```

При наличии распакованного проверяемого плагина можно отдельно выполнить
`python3 -B run_cli_smoke.py --plugin-root /path/to/unpacked/plugin`.
Этот сценарий читает четыре TXT из P01 через поставляемый адаптер, проверяет
их SHA-256 и целостность пакета до/после. Он не запускает модель, OCR,
установку зависимостей или юридическую проверку. Номер реально проверенной
версии записывается в `cli-smoke-report.json`; его нельзя автоматически
переносить на другую версию или другой хост.

Сценарии предназначены для проверки плагина и формы review; они не являются оценкой вероятности принятия жалобы, производственной аттестацией, юридическим одобрением или поручением направить какие-либо документы.
