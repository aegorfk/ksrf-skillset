# Написание и предлагаемая редакция жалобы

Добавлен локальный маршрут `writing plan/compose/review/revise/status`. Он связывает концепцию вопроса, основания абзацев, возражения и изменения текста с конкретными сохранёнными версиями. Подготовку содержания выполняет агент по скиллам; CLI проверяет связи и сохраняет предложенный текст без обращения к нейросети или внешнему сервису.

## Что получает пользователь

- Концепцию с альтернативами, предлагаемой ведущей формулировкой и неизвестными обстоятельствами.
- Карту доводов с тезисом, точной цитатой, объяснением применимости, возражением, ответом и выводом.
- Сохранённый исходник, отдельную редакцию, сравнение текстов и объяснение каждого изменения.
- Перечень замечаний с историей: после изменения абзаца прежнее addressed становится needs_recheck.
- Готовый вход для штатного `render draft` и проверку сохранённых файлов через `writing status`.

Инструкция и входные поля: [сохраняемый редакторский цикл](../skills/ksrf-complaint-cycle/references/complaint-writing-loop.md).

## Границы

Проверка цитаты устанавливает только её точное совпадение с локальным текстовым объектом. Роль автора, подлинность, актуальность, применимость и достаточность оснований требуют содержательной проверки. Объявленная сила вывода проверяется по записанным функциям доказательств; модуль не является семантическим классификатором и не обнаруживает каждое скрытое усиление формулировки. Все изменённые абзацы предъявляются человеку.

Предложенный проект очищается от approvals и formal_check; все строки имеют pending. Машинная редакторская отметка addressed не является независимым юридическим одобрением. Строгие render/release сохраняют прежние требования. Команды одного дела выполняются последовательно; CLI отклоняет уже устаревшего родителя, но параллельная совместная редактура не заявлена.

## Проверка

Целевой набор: `python -m unittest discover -s tests -p test_writing_loop.py -v` — 21 тест. Проверяются полный CLI-цикл, русская справка, точность Unicode-цитат, исходник и сброс approvals, устаревшие хеши, сохранение замечаний, повторная проверка, усиление вывода, чужое дело, источник под прежним ID, повреждённые пакеты/файлы/источники и совместимость с рабочим экспортом.

Синтетический сквозной сценарий прошёл plan → compose → review → revise → review → status → render draft. Он проверяет работоспособность программного пути. Увеличение качества юридических доводов или вероятности принятия жалобы этим прогоном не измеряется. Частные материалы и результаты локальных запусков в репозиторий не входят.

Проверка ядра: 441 тест, без ошибок. Полный общий прогон выполнил 404 теста (2 пропуска) и выявил пять несовпадений в четырёх тестах с прежними счётчиками CLI и отпечатком инструкции. Ожидания обновлены под проверенный состав; затем 32 проверки, включая все затронутые проверки и новый редакторский цикл, прошли без ошибок. Полный общий набор после этой корректировки ожиданий повторно не запускался. Финальная установка в отдельную папку и её автономная проверка прошли для 15 навыков; source strict validator пройден для 15 навыков без ошибок и предупреждений, OpenSpec — 43/43 после синхронизации и архивирования change.
