# Сборка плагина для заявителей

Источник методологии и runtime — канонический `aegorfk/ksrf-skillset`. Глобальная
пользовательская установка остаётся в `~/.codex/skills`. Готовый плагин — результат
сборки по `tools/skillset_file_contract.py`, не отдельный источник правок.

## Состав

Включаются все 16 навыков, их runtime-файлы, схемы и справочники, лицензия,
инструкция заявителя, проверка целостности и воспроизводимая контейнерная среда.
Source-only tests/evals, исходные жалобы, OCR, частные приложения, настройки
доступа, ключи, локальные базы и runtime-каталоги в пакет не входят.

Основной вход заявителя — `ksrf-complaint-cycle` и его
`references/applicant-start.md`. Прямые интерфейсы всех навыков сохраняются.
Состав маршрутов проверяется по [каталогу сценариев](../plugin/use-cases.json);
его 20 сценариев описывают ожидаемое поведение. Наличие сценария в каталоге
не означает, что он был исполнен моделью или проверен заявителем.

## Подготовить пакет

Из чистого опубликованного checkout:

```sh
python3 tools/build_applicant_plugin.py --require-clean --output /absolute/new/output-directory
```

Выход обязан быть новой папкой вне исходного репозитория. Сборка без
`--require-clean` предназначена для испытаний; такой манифест честно указывает
на изменённое рабочее дерево и не подтверждает публикацию. Режим выпуска
проверяет чистоту, канонический remote, актуальный live SHA и исходный манифест
до и после сборки. Изменение входных байтов во время сборки отклоняется.

Результат:

- `web/ksrf-applicant/` и `desktop/ksrf-applicant/` — полные пакеты;
- два ZIP с фиксированным порядком файлов и временем архивных записей;
- `SHA256SUMS`, `build-report.json` и внутренний `distribution-manifest.json`;
- `marketplace/` — генерируемый GitHub marketplace с готовым плагином.

Оба варианта содержат одни исходные навыки и runtime. Отличается описание
целевой среды в `surface.json`; выполнение всё равно определяется
инструментами конкретного хоста. Браузерный пакет не объявляет локальные MCP
серверы. Контейнер — локальная среда исполнения, не размещённый HTTPS-сервис.

## Проверить

```sh
python3 verify.py --json
python3 skills/ksrf-complaint-cycle/scripts/plugin_runtime.py doctor --json
python3 skills/ksrf-complaint-cycle/scripts/validate_ksrf_skillset.py --skills-root skills --profile runtime --strict
```

Команды выше выполняются из корня готового пакета. Целостность файла не
устанавливает происхождение сама по себе: доверенный SHA источника и место
получения пакета проверяются отдельно. Runtime-профиль не заменяет source QA.
Контейнерная проверка описана в [инструкции исходного репозитория](../plugin/environment/README.md)
и `environment/README.md` готового пакета.

## Опубликовать

Сначала выполнить выпуск канонического источника по [контракту публикации](PUBLICATION_CONTRACT.md).
Затем собрать заново с `--require-clean`, опубликовать точный генерируемый
marketplace и ZIP с проверенными контрольными суммами. Полученный публичный
архив скачать повторно, сравнить SHA-256 и проверить чистую установку.

GitHub-дистрибуция, установка в конкретный аккаунт ChatGPT, размещение среды
исполнения и принятие в общий каталог OpenAI — отдельные результаты.
Не обозначать один из них выполненным по факту другого.

Для ChatGPT описан импорт marketplace администратором рабочего пространства,
если он доступен на его тарифе и с его правами. При подготовке этого выпуска
импорт внутри авторизованного аккаунта ChatGPT не проверен; размещённого
облачного runtime нет. Локальная контейнерная проверка не закрывает эти два
ограничения. Пользовательские инструкции приведены в [README плагина](../plugin/README.md).
