# Скиллы для жалоб в КС РФ

LegalTech-инструментарий для юристов и заявителей, которые готовят обращение в Конституционный Суд. Скиллы помогают пройти полный цикл — от первичной проверки допустимости до подготовки комплекта документов.

# Что это и зачем
Подготовка жалобы в КС РФ — это не кассация. Здесь нельзя просто пожаловаться на несправедливость: нужна строгая связка **норма → применение в деле → конституционно-правовая проблема → исчерпание → срок**. Ошибка в любом звене может остановить обращение уже на предварительной проверке Секретариата; его уведомление не является решением Конституционного Суда, и заявитель вправе в предусмотренных законом случаях повторно направить исправленное обращение либо потребовать разрешить вопрос в порядке статьи 40 ФКЗ о КС РФ.

Этот набор скиллов превращает методологию конституционных юристов, научные подходы, официальную практику КС РФ и опыт работы с реальными материалами дел в инструменты, которые работают прямо в вашем рабочем процессе.

## Установка на чистый ноутбук

Для обычной работы не нужны научная библиотека, локальный архив актов, проект `ks_parser_lower_court_marker`, Telegram-выгрузки, Qdrant, Neo4j или платный юридический сервис. В репозитории уже находятся все 13 skills, автономное практическое ядро, методические карточки, шаблоны и QA-правила.

Базовый технический минимум — Git, Bash и Python 3. Если `rsync` отсутствует, installer использует системный `cp`. Без Python остаются доступными все инструкции и справочники, но не запускаются автоматические валидаторы и автосбор. PDF/OCR-утилиты необязательны: при их отсутствии skill фиксирует пробел извлечения и запрашивает читаемый документ вместо имитации распознавания.

```bash
git clone https://github.com/aegorfk/ksrf-skillset.git
cd ksrf-skillset
./install.sh
python3 "${CODEX_HOME:-$HOME/.codex}/skills/ksrf-complaint-cycle/scripts/verify_offline_self_containment.py"
```

Для установки в иной каталог без изменения `HOME` или `CODEX_HOME`:

```bash
./install.sh --target /path/to/codex/skills
python3 /path/to/codex/skills/ksrf-complaint-cycle/scripts/verify_offline_self_containment.py
```

Единственные внешние данные, которые нельзя безопасно «вшить», — факты конкретного дела и актуальная редакция официального права. Их skill получает из документов пользователя или официальных интернет-источников. Если источник недоступен, результат должен содержать `official_source_unavailable` или `case_document_missing`, а не вымышленную норму, цитату или факт. Исходная научная работа нужна только для прямой цитаты, новой атрибуции или выхода за пределы встроенной методической карточки.

## Методология как цифровой маршрут

Скиллы не подставляют факты в универсальный шаблон. Они проводят дело через последовательный маршрут: собирают документы, проверяют допустимость, находят нормативный механизм вреда, отделяют конституционный вопрос от спора о фактах, строят альтернативные аргументы и помогают собрать управляемый проект жалобы.

Повторяемые операции автоматизированы, но окончательная правовая позиция и решение о подаче остаются за человеком. Это позволяет раньше увидеть критические пробелы, сосредоточиться на содержательной работе и понять, на каком этапе требуется профессиональная юридическая проверка.

# Что умеют скиллы
##  Проверка допустимости
- Определяет, направлено ли требование на норму, а не на пересмотр фактов
- Проверяет цепочку инстанций по типу судопроизводства (ГПК / АПК / КАС / УПК / КоАП) и находит недостающие стадии
- Рассчитывает годичный срок и отдельно проверяет, сохраняется ли дата первичной подачи при устранении недостатков в течение четырёх месяцев после уведомления Секретариата (ст. 40 и п. 2 ст. 97 ФКЗ о КС РФ)

##  Типология и тестовая проверка
Классифицирует дело по типу конституционно-правовой проблемы и задаёт релевантные проверочные вопросы:

##  Ключевые вопросы теста
**Пропорциональность ограничения:**	Введено ли законом? Есть ли законная цель? Необходима ли мера?
**Равенство / запрет дискриминации:**	Есть ли различие? Одна ли категория лиц? Оправдано ли?
**Правовая определённость:**	Есть ли пробел? Разнобой практики? Нарушены ли права?
**Запрет обратной силы:**	Применена ли норма к прошлым отношениям? Ухудшила ли положение?
**Защита законных ожиданий:**	Изменилось ли регулирование? Были ли ожидания правомерны?

##  Генерация аргументации и жалобы
- Строит аргументацию в логике IRAC (Issue → Rule → Application → Conclusion)
- Формирует конституционно-правовую проблему по формуле: «норма не соответствует Конституции в той мере, в какой по буквальному смыслу и/или по смыслу правоприменительной практики приводит к X, нарушая Y»
- Генерирует все разделы жалобы: адресат, сведения о заявителе, предмет, право на обращение, факты, конституционный вопрос, аргументация, требование к КС, перечень приложений
- Подбирает паттерны нарушения (дискриминация, несоразмерность, правовая неопределённость, ретроактивность, блокирование доступа к суду) с типовыми формулами (insofar as)

##  Опора на практику высших судов
- Использует CasusLegal MCP как подключаемый канал поиска практики КС РФ, ВС РФ и ВАС РФ, если у пользователя есть доступ к сервису
- Разделяет конституционную доктрину КС РФ, судебный смысл нормы, доказательства его применения и историческую практику
- Проверяет редакцию нормы, временной контекст, переносимость позиции, adverse/refusal-практику и точные locators
- Формирует authority ledger и блоки «тезис → позиция → мост применимости → вывод» вместо каталога ссылок
- Не сохраняет токены подписки и не переносит приватные access-ссылки в публичные материалы или процессуальный документ

##  Формальная проверка
Валидирует комплектность по ст. 37–38 ФКЗ о КС РФ
Проверяет полномочия и категорию представителя: представитель по должности или закону либо адвокат/лицо с учёной степенью по юридической специальности; у каждой стороны — не более трёх представителей (ст. 53 ФКЗ о КС РФ)
Контролирует наличие госпошлины или ходатайства об освобождении
Предупреждает, если жалоба фактически спорит с судебным актом, а не с нормой

## Состав

- `skills/ksrf-argument-patterns` - корпусные паттерны конституционно-правовой аргументации, извлеченные из Постановлений КС РФ.
- `skills/ksrf-practice-authority-builder` - проверяемая опора на практику высших судов, authority ledger, adverse pass и органичное встраивание позиций в аргумент.
- `skills/ksrf-echr-argumentation` - практика ЕСПЧ, guides и HUDOC как проверяемый сравнительный слой для конституционных жалоб и обращений в ЕСПЧ.
- `skills/ksrf-*` - глобальные KSRF-скиллы для цикла жалобы, интегрированные с корпусным слоем паттернов.
- `tools/` - необязательные maintenance-скрипты для повторного извлечения и обогащения справочников; для использования skills не нужны.
- `openspec/changes/extract-ksrf-argument-pattern-skills` - спека с требованиями и дизайном.

## Автономная работа

Все KSRF-скиллы подключены к `skills/ksrf-complaint-cycle/references/offline-practice-core.md`; оркестратор дополнительно использует `strategic-complaint-design.md`. В этих справочниках собрана переносимая методология полного цикла: выбор маршрута и нормативного носителя, допустимость, прямое и фактическое применение нормы, anti-appeal проверка, построение аргумента, внешний эффект решения, drafting, подача, исполнение и расходы.

Telegram-каналы, методические сайты и локальные исследовательские корпуса используются только для provenance и будущего обновления. Их отсутствие не блокирует работу скиллов. Актуальные нормы и факты конкретного дела по-прежнему проверяются по официальным источникам и документам дела.

CasusLegal MCP также является необязательным расширением: при действующей подписке он ускоряет поиск и проверку практики высших судов, а при недоступном коннекторе skillset продолжает работать по встроенному автономному ядру и переданным официальным источникам. Персональный токен в этот репозиторий не включается.

Автономность набора проверяется командой:

```bash
python3 skills/ksrf-complaint-cycle/scripts/verify_offline_self_containment.py
```

## Необязательная перегенерация справочников

Этот раздел предназначен только для сопровождающего набора и не является шагом установки. Обычная работа использует уже включённые справочники. Если у сопровождающего есть собственный корпус, все пути передаются явно:

Из исходного проекта, где есть `analysis_results/ksrf_argument_patterns`:

```bash
KSRF_PROJECT_ROOT=/path/to/ks_parser_lower_court_marker
python3 tools/enrich_ksrf_argument_patterns.py \
  --analysis "$KSRF_PROJECT_ROOT/analysis_results/ksrf_argument_patterns" \
  --skill ./skills/ksrf-argument-patterns
```

## Источник правды и публикация

Рабочая копия навыков живет глобально в `~/.codex/skills`. Этот репозиторий — публикуемое зеркало KSRF skillset.

Точный состав опубликованного набора, исключения и контрольные суммы находятся в [`skills-manifest.json`](skills-manifest.json).

После существенных правок глобальных навыков нужно периодически обновлять репозиторий:

1. подтянуть свежий remote, чтобы сохранить актуальный `README.md`;
2. синхронизировать `~/.codex/skills/ksrf-*` в `skills/`;
3. обновить `tools/` из штатных скриптов глобальных навыков;
4. проверить, что в репозиторий не попали `__pycache__`, `.DS_Store` и временные файлы;
5. закоммитить и запушить изменения.

Для синхронизации всего набора используйте `tools/sync_global_skills.sh`; команда зеркалирует все глобальные навыки `ksrf-*` в каталог `skills/` без затрагивания остальных файлов репозитория.

## Заметки

Граф конституционно-правовой аргументации хранится в переносимом JSON/Markdown:

- `skills/ksrf-argument-patterns/references/constitutional_graph.json`
- `skills/ksrf-argument-patterns/references/constitutional-graph.md`

Для запуска отдельная графовая база не нужна. Граф содержит:
- повторяющиеся структуры доводов по каждому типу дел
- связи «норма Конституции → тест → типовая формулировка»
- корпусные частоты и контексты применения конкретных статей
