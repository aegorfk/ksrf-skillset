# Скиллы для жалоб в КС РФ

LegalTech-инструментарий для юристов, работающих с конституционными жалобами. Скиллы автоматизируют полный цикл — от проверки допустимости до генерации готового комплекта документов.

# Что это и зачем
Подготовка жалобы в КС РФ — это не кассация. Здесь нельзя просто пожаловаться на несправедливость: нужна строгая связка **норма → применение в деле → конституционно-правовая проблема → исчерпание → срок**. Ошибка в любом звене — отказ секретариата ещё до судьи.

Этот набор скиллов кодирует методологию конституционных юристов и контитуционно-правовую аргументацию из реальных Постановлений КС РФ и успешных жалоб в инструменты, которые работают прямо в вашем рабочем процессе.

# Что умеют скиллы
##  Проверка допустимости
- Определяет, направлено ли требование на норму, а не на пересмотр фактов
- Проверяет цепочку инстанций по типу судопроизводства (ГПК / АПК / КАС / УПК / КоАП) и находит недостающие стадии
- Рассчитывает годичный срок с учётом 4-месячного окна секретариата (ст. 40 ФКЗ о КС РФ)

##  Типология и тестовая проверка
Классифицирует дело по типу конституционно-правовой проблемы и задаёт релевантные проверочные вопросы:

##  Ключевые вопросы теста
**Пропорциональность ограничения:**	Введено ли законом? Есть ли законная цель? Необходима ли мера?
**Равенство / запрет дискриминации:**	Есть ли различие? Одна ли категория лиц? Оправдано ли?
**Правовая определённость:**	Есть ли пробел? Разнобой практики? Нарушены ли права?
**Запрет обратной силы:**	Применена ли норма к прошлым отношениям? Ухудшила ли положение?
**Защита законных ожиданий:**	Изменилось ли регулирование? Были ли ожидания правомерны?

##  Генерация аргументации и жалобы
- Строит аргументацию в логике IRAC (Issue → Rule → Application → Conclusion)
- Формирует конституционно-правовую проблему по формуле: «норма не соответствует Конституции в той мере, в какой по буквальному смыслу и/или по смыслу правоприменительной практики приводит к X, нарушая Y»
- Генерирует все разделы жалобы: адресат, сведения о заявителе, предмет, право на обращение, факты, конституционный вопрос, аргументация, требование к КС, перечень приложений
- Подбирает паттерны нарушения (дискриминация, несоразмерность, правовая неопределённость, ретроактивность, блокирование доступа к суду) с типовыми формулами (insofar as)

##  Формальная проверка
Валидирует комплектность по ст. 37–38 ФКЗ о КС РФ
Проверяет реквизиты представителя (адвокат или учёная степень, ≤ 3 представителей)
Контролирует наличие госпошлины или ходатайства об освобождении
Предупреждает, если жалоба фактически спорит с судебным актом, а не с нормой

## Состав

- `skills/ksrf-argument-patterns` - корпусные паттерны конституционно-правовой аргументации, извлеченные из Постановлений КС РФ.
- `skills/ksrf-echr-argumentation` - практика ЕСПЧ, guides и HUDOC как проверяемый сравнительный слой для конституционных жалоб и обращений в ЕСПЧ.
- `skills/ksrf-*` - глобальные KSRF-скиллы для цикла жалобы, интегрированные с корпусным слоем паттернов.
- `tools/` - локальные скрипты для извлечения и обогащения корпуса конституционно-правовой аргументации.
- `openspec/changes/extract-ksrf-argument-pattern-skills` - спека с требованиями и дизайном.

## Автономная работа

Все KSRF-скиллы подключены к `skills/ksrf-complaint-cycle/references/offline-practice-core.md`; оркестратор дополнительно использует `strategic-complaint-design.md`. В этих справочниках собрана переносимая методология полного цикла: выбор маршрута и нормативного носителя, допустимость, прямое и фактическое применение нормы, anti-appeal проверка, построение аргумента, внешний эффект решения, drafting, подача, исполнение и расходы.

Telegram-каналы, методические сайты и локальные исследовательские корпуса используются только для provenance и будущего обновления. Их отсутствие не блокирует работу скиллов. Актуальные нормы и факты конкретного дела по-прежнему проверяются по официальным источникам и документам дела.

Автономность набора проверяется командой:

```bash
python3 skills/ksrf-complaint-cycle/scripts/verify_offline_self_containment.py
```

## Перегенерация справочников обогащения

Из исходного проекта, где есть `analysis_results/ksrf_argument_patterns`:

```bash
python3 tools/enrich_ksrf_argument_patterns.py \
  --analysis /Users/aegorfk/Documents/ks_parser_lower_court_marker/analysis_results/ksrf_argument_patterns \
  --skill ./skills/ksrf-argument-patterns
```

## Источник правды и публикация

Рабочая копия навыков живет глобально в `~/.codex/skills`. Этот репозиторий — публикуемое зеркало KSRF skillset.

После существенных правок глобальных навыков нужно периодически обновлять репозиторий:

1. подтянуть свежий remote, чтобы сохранить актуальный `README.md`;
2. синхронизировать `~/.codex/skills/ksrf-*` в `skills/`;
3. обновить `tools/` из штатных скриптов глобальных навыков;
4. проверить, что в репозиторий не попали `__pycache__`, `.DS_Store` и временные файлы;
5. закоммитить и запушить изменения.

Для синхронизации всего набора используйте `tools/sync_global_skills.sh`; команда зеркалирует все глобальные навыки `ksrf-*` в каталог `skills/` без затрагивания остальных файлов репозитория.

## Заметки

Граф конституционно-правовой аргументации хранится в переносимом JSON/Markdown:

- `skills/ksrf-argument-patterns/references/constitutional_graph.json`
- `skills/ksrf-argument-patterns/references/constitutional-graph.md`

Для запуска отдельная графовая база не нужна. Граф содержит:
- повторяющиеся структуры доводов по каждому типу дел
- связи «норма Конституции → тест → типовая формулировка»
- корпусные частоты и контексты применения конкретных статей
